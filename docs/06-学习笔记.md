## 1. 项目全貌（课程 0.1）

### 1.1 一句话

用户输入生辰，后端用**确定性算法**排出紫微斗数命盘，再用**规则引擎**判断格局，然后从**本地知识库**检索依据，交给 DeepSeek **流式**生成解读，前端用 React 把命盘和文字**逐段动画呈现**。

### 1.2 分层架构

```text
浏览器（React）
   │  HTTP / JSON / SSE
   ▼
FastAPI（接口层）
   │
   ├── 排盘服务（iztro-py）        ← 确定性，不调用 LLM
   ├── 规则引擎（格局/四化/运限）   ← 确定性，不调用 LLM
   ├── RAG（Chroma + BM25）        ← 检索依据
   ├── LLM 编排（LangGraph）       ← 推理与成文
   └── SQLite（历史/会话/引用）     ← 持久化
```

**关键边界**：计算归计算，生成归生成。

- 排盘、四化、格局：必须由代码算，结果可复现、可测试。
- 语言组织、类比、追问：交给 LLM。
- 两者之间用**结构化 JSON** 连接，而不是让 LLM 读自然语言命盘。

### 1.3 一次请求的完整生命周期

以“排盘”为例：

```text
1. 用户在 React 表单填：1991-08-15 01:00 男
2. 前端 fetch POST /api/v1/charts，body 是 JSON
3. Uvicorn 收到 HTTP 请求，交给 FastAPI
4. FastAPI 用 Pydantic 校验字段（日期合法？时辰 0-12？性别？）
5. 路由函数调用 service，service 调用 domain/chart
6. domain/chart 调用 iztro-py 算出十二宫
7. 规则引擎追加格局、四化、大限、流年压力
8. 结果存入 SQLite，返回 chart_id + JSON
9. 前端拿到 JSON，渲染十二宫并播放动画
```

以“解读”为例：

```text
1. 前端打开 SSE 连接 GET /api/v1/readings/{id}/stream
2. FastAPI 先检索知识库，拿到 top-k 片段
3. 调用 deepseek-reasoner，流式收到 reasoning_content
4. 每收到一段，就通过 SSE 推给前端
5. 推理结束后调用 deepseek-chat 生成正文，继续流式推送
6. 前端边收边渲染，最后显示引用和免责声明
```

### 1.4 为什么排盘不能交给 LLM

| 问题 | 说明 |
|---|---|
| 不可复现 | 同一生辰两次调用，模型可能给出不同星曜位置 |
| 不可测试 | 没有确定答案，无法写断言 |
| 不可解释 | 用户问“为什么紫微在午宫”，模型只能编 |
| 成本高 | 每次排盘都烧 token，而排盘本可以 1ms 算完 |
| 容易错 | 安星、四化、亮度都是查表规则，模型没有表 |

所以本项目把排盘做成**工具**：LLM 可以调用它，但不能改写它的结果。

**为什么这样分**：

- `api` 只负责 HTTP，不写业务。

- `tests` 与业务代码平行，测试文件路径能对应到模块。

| 前端/后端 | 前端管界面，后端管数据与计算 |
| API | 前后端约定好的调用入口 |
| endpoint | 一个具体的 API 地址，如 `/api/v1/charts` |
| HTTP | 浏览器和服务端说话的语言 |
| JSON | 双方交换数据的格式 |
| SSE | 服务器持续向浏览器推送文本的技术 |
| 环境变量 | 不写进代码的配置，如 API Key |
| 确定性 | 同样输入永远得到同样输出 |

### 2.3 `.gitignore`、`.env`、`.env.example` 的区别

| 文件 | 是否提交 | 作用 |
|---|---|---|
| `.gitignore` | 提交 | 告诉 Git 哪些文件不要管 |
| `.env` | **不提交** | 本机真实密钥与配置 |
| `.env.example` | 提交 | 配置模板，告诉别人需要哪些变量 |

本项目 `.gitignore` 已包含：

```text

_refs/
data/uploads/
data/chroma/
*.db
node_modules/
__pycache__/
```

验证某个文件是否被忽略：

```bash
git check-ignore -v .env
# 输出：.gitignore:5:.env    .env
```

**最容易犯的错**：把 `.env` 提交上去。提交后再删除也仍在历史里，必须轮换 Key。

### 2.4 conda 常用命令

```bash
conda env list                  # 列出环境
conda create -n ziwei python=3.11 -y
conda activate ziwei            # 激活
conda deactivate                # 退出
conda remove -n ziwei --all     # 删除环境（慎用）
```

本项目实际创建时遇到 SSL 问题，最终命令是：


**为什么用独立环境**：不同项目依赖版本冲突；独立环境删掉不影响 base；部署时容易复现。

- `alembic`：数据库结构变更的版本管理。
- `iztro-py`：排盘引擎，避免自己实现安星表。
- `pytest`：写测试。

## 4. 测试入门（课程 0.4）

### 4.1 测试的本质

```text
安排（Arrange）→ 执行（Act）→ 断言（Assert）
```

```python
def test_add():
    result = 1 + 1      # 执行
    assert result == 2  # 断言
```

- **安排**：准备输入、测试数据、依赖。
- **执行**：调用被测函数或接口。
- **断言**：用 `assert` 检查结果是否符合预期。

测试不是“证明程序没有 bug”，而是“证明某个行为仍然符合约定”。以后改代码时，测试会告诉你有没有破坏旧行为。

### 4.2 pytest 怎么找到测试

pytest 默认规则：

- 文件名：`test_*.py` 或 `*_test.py`
- 函数名：`test_*`
- 类名：`Test*`（类里的方法也要 `test_*`）

本项目在 `backend/pyproject.toml` 里固定了测试目录：

```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
pythonpath = ["."]
addopts = "-q"
asyncio_default_fixture_loop_scope = "function"
```

- `testpaths`：只去 `tests/` 找。
- `pythonpath`：把 `backend/` 加入导入路径，测试里才能 `from app...`。
- `addopts = "-q"`：精简输出。
- `asyncio_default_fixture_loop_scope`：消除 pytest-asyncio 的弃用警告。

### 4.3 fixture：把重复的准备抽出来

```python
import pytest

@pytest.fixture(scope="module")
def chart():
    return astro.by_solar("1991-8-15", 1, "男", "zh-CN")


def test_palace_count(chart):
    assert len(chart.palaces) == 12
```

- 测试函数只要写参数名 `chart`，pytest 就会自动调用同名 fixture，把返回值传进来。
- `scope="module"`：整个测试文件只排一次盘，多个用例复用，避免重复计算。
- 默认 `scope="function"`：每个用例都重新执行一次，隔离性最好。

### 4.4 参数化：一份逻辑测多组输入

```python
@pytest.mark.parametrize(
    ("hour", "expected"),
    [(0, 0), (1, 1), (2, 1), (23, 12)],
)
def test_hour_to_index(hour, expected):
    assert hour_to_index(hour) == expected
```

pytest 会生成 4 个独立用例。失败时能直接看到是哪一组输入错了。

### 4.5 断言异常

```python
def test_invalid_hour():
    with pytest.raises(ValueError, match="hour"):
        hour_to_index(24)
```

- `pytest.raises`：断言这段代码会抛异常。
- `match`：用正则匹配异常信息，避免“抛了别的异常也算通过”。

### 4.7 为什么先写这个函数

- 它是排盘前必须做的一步：用户输入 23:30，必须知道这是“晚子”而不是“早子”。
- 它是纯函数：不依赖网络、数据库、API Key，测试跑得极快。
- 它边界多：0 点、23 点、每个时辰的起止，适合练参数化。
- 它以后会被 `domain/chart/engine.py` 调用，不是玩具代码。

### 4.8 逐行读 `test_time.py`

```python
import pytest

from app.domain.chart.time import hour_to_index
```

- `import pytest`：导入测试框架，后面要用 `pytest.mark.parametrize` 和 `pytest.raises`。
- `from app.domain.chart.time import hour_to_index`：导入被测函数。`app` 能被导入，是因为 `pyproject.toml` 里配置了 `pythonpath = ["."]`。

```python
@pytest.mark.parametrize(
    ("hour", "expected"),
    [
        (0, 0),
        (1, 1),
        ...
        (23, 12),
    ],
)
def test_hour_to_index(hour: int, expected: int) -> None:
    assert hour_to_index(hour) == expected
```

逐部分解释：

| 部分 | 含义 |
|---|---|
| `@pytest.mark.parametrize(...)` | 装饰器，告诉 pytest：这个函数要跑多组数据 |
| `("hour", "expected")` | 参数名，顺序和下面的元组对应 |
| `[(0, 0), (1, 1), ...]` | 每组输入和期望输出 |
| `def test_hour_to_index(hour, expected)` | pytest 会把每组值自动传进来 |
| `-> None` | 类型标注：测试函数不返回结果 |
| `assert hour_to_index(hour) == expected` | 断言实际结果等于期望结果 |

pytest 会把 24 组数据拆成 24 个独立用例，名字类似：

```text
test_hour_to_index[0-0]
test_hour_to_index[1-1]
...
test_hour_to_index[23-12]
```

哪一组失败，名字里直接能看出来。

```python
def test_hour_to_index_rejects_out_of_range() -> None:
    with pytest.raises(ValueError, match="hour"):
        hour_to_index(24)
```

- `pytest.raises(ValueError)`：断言这段代码**必须抛出** `ValueError`。
- 如果没抛异常，测试失败，提示 `DID NOT RAISE`。
- 如果抛了别的异常（比如 `TypeError`），测试也失败。
- `match="hour"`：用正则匹配异常信息，确保是“小时超范围”的那个 `ValueError`，而不是碰巧同类型的别的错误。

### 4.10 `@pytest.fixture(scope="module")` 到底是什么

拆成三层看：

#### 第一层：装饰器

装饰器是“接收一个函数，返回一个增强版函数”的函数。

```python
def my_decorator(func):
    def wrapper():
        print("调用前")
        func()
        print("调用后")
    return wrapper


@my_decorator
def hello():
    print("hello")
```

等价于：

```python
hello = my_decorator(hello)
```

`@` 只是语法糖。

#### 第二层：pytest.fixture

```python
@pytest.fixture(scope="module")
def chart():
    return astro.by_solar(...)
```

`pytest.fixture(scope="module")` 本身是一个“装饰器工厂”：

1. 先执行 `pytest.fixture(scope="module")`，得到一个装饰器。
2. 再用这个装饰器处理 `chart` 函数。
3. pytest 给函数打上标记：这是一个 fixture，不是测试。
4. 测试收集阶段，pytest 发现某个测试函数有参数 `chart`，就去找同名 fixture。
5. 找到后调用它，把返回值传进测试函数。

这叫**依赖注入**：测试函数不关心数据怎么来的，只声明“我需要一个 chart”。

#### 第三层：scope

`scope` 控制 fixture 多久重新创建一次：

| scope | 生命周期 | 适用 |
|---|---|---|
| `function` | 每个测试函数一次（默认） | 需要完全隔离 |
| `class` | 每个测试类一次 | 类内共享 |
| `module` | 每个测试文件一次 | 排盘这种较重、只读的数据 |
| `package` | 每个包一次 | 跨文件共享 |
| `session` | 整个测试会话一次 | 数据库连接、临时目录 |

本项目的排盘结果是只读的，4 个测试都查同一张盘，所以用 `module`，只排一次，速度快。

如果某个测试会修改 fixture 返回的对象，就不能用 `module`，否则会污染其他测试；这时用默认的 `function`，每次给一份新的。

#### fixture 的清理

如果 fixture 需要清理资源，用 `yield`：

```python
@pytest.fixture
def temp_file():
    f = open("tmp.txt", "w", encoding="utf-8")
    yield f
    f.close()
```

`yield` 之前是准备，`yield` 之后是清理。

### 4.11 断言是什么

`assert` 是 Python 关键字：

```python
assert 条件
```

- 条件为真：程序继续。
- 条件为假：抛出 `AssertionError`，当前测试失败。

```python
def test_demo():
    assert 1 + 1 == 3
```

pytest 会显示：

```text
assert 2 == 3
```

它会把你写的表达式“拆开”，把实际值显示出来，这就是 pytest 的断言重写。

注意：

- 测试里用 `assert` 是标准做法。
- 业务代码里不要用 `assert` 校验用户输入，因为 `python -O` 会移除断言；应该用 `if ...: raise ValueError(...)`。
- `assert` 后面可以加说明：`assert x == y, "x 应该等于 y"`，但 pytest 通常已经能显示足够信息。

### 4.12 为什么测试函数不需要 `return`

测试的“结果”不是返回值，而是：

- 全部断言通过 → 测试通过。
- 任意断言失败 → 测试失败。

所以测试函数通常写 `-> None`，也不写 `return`。

### 4.18 `pyproject.toml` 里放的是什么

当前内容：

```toml
[tool.pytest.ini_options]
testpaths = ["tests"]
pythonpath = ["."]
addopts = "-q"
asyncio_default_fixture_loop_scope = "function"
```

`pyproject.toml` 是 Python 项目的标准配置文件，用 TOML 语法。它可以放：

- 项目元数据：名称、版本、作者、依赖；
- 构建系统：用 setuptools / hatchling / poetry；
- 工具配置：pytest、ruff、mypy、black 等。

当前项目只放了 pytest 配置，因为依赖是直接用 pip 装的，还没做打包。

#### TOML 语法速记

```toml
[section]              # 表（类似字典）
key = "value"          # 字符串
number = 42            # 整数
flag = true            # 布尔
list = ["a", "b"]      # 数组
```

`[tool.pytest.ini_options]` 就是“tool 表里的 pytest 表里的 ini_options 表”。

#### 每一项的意思

**`testpaths = ["tests"]`**

pytest 只去 `tests/` 目录找测试，不去翻 `app/`、`data/`、`node_modules/`。速度快，也不会误把业务代码当测试。

**`pythonpath = ["."]`**

把 `backend/` 加入 `sys.path`，这样测试里才能：

```python
from app.domain.chart.time import hour_to_index
```

没有这一行，通常会报：

```text
ModuleNotFoundError: No module named 'app'
```

等价的手动做法是：

```bat
set PYTHONPATH=.
python -m pytest
```

但写进配置更稳定，不依赖你记不记得设环境变量。

**`addopts = "-q"`**

给每次 pytest 运行默认加参数。这里加 `-q`，所以默认输出是点。

想临时覆盖：

```bat
python -m pytest -o addopts="" -v
```

**`asyncio_default_fixture_loop_scope = "function"`**

这是 `pytest-asyncio` 的配置，不是 pytest 核心的。

- 异步 fixture 需要一个事件循环；
- 这个选项决定事件循环的作用域；
- `function` 表示每个测试函数一个循环，隔离性最好；
- 不设置会看到弃用警告。

以后写异步 API 测试时，可能还会加：

```toml
asyncio_mode = "auto"
```

- `strict`（默认）：异步测试要显式标 `@pytest.mark.asyncio`；
- `auto`：只要 `async def test_...` 就自动当异步测试。

现在还没写异步测试，所以先不设。

#### pytest 怎么找到这个配置

在 `backend/` 目录运行 pytest 时，它会向上查找配置文件，找到 `pyproject.toml` 里的 `[tool.pytest.ini_options]`，然后：

- `rootdir` 设为 `backend/`
- `configfile` 显示 `pyproject.toml`
- `testpaths` 设为 `tests`

运行输出里的这几行就是证据：

```text

testpaths: tests
```

因为配置、`tests/`、`app/` 都是相对 `backend/` 的。在项目根目录直接跑：

```bat

```

pytest 可能找不到 `pyproject.toml`，也可能找不到 `tests/`，还会因为 `app` 不在 `sys.path` 而导入失败。

### 4.20 深入理解 `with pytest.raises(...)`

```python
def test_hour_to_index_rejects_out_of_range() -> None:
    with pytest.raises(ValueError, match="hour"):
        hour_to_index(24)
```

#### 先看 `with` 的本质

`with` 不是“捕获异常”的语法，它只是**上下文管理器协议**：

```python
with 某个对象:
    代码块
```

执行过程：

1. 调用对象的 `__enter__()`；
2. 执行代码块；
3. 不管代码块正常结束还是抛异常，都调用对象的 `__exit__(...)`；
4. `__exit__` 返回 `True` 表示“异常被我处理掉了”，返回 `False` 表示“继续往外抛”。

一个最小例子：

```python
class Demo:
    def __enter__(self):
        print("进入")
        return self

    def __exit__(self, exc_type, exc, tb):
        print("离开")
        return False


with Demo():
    print("中间")
```

输出：

```text
进入
中间
离开
```

`pytest.raises(...)` 返回的就是一个这样的上下文管理器，只是它的 `__exit__` 会检查异常类型和信息。

#### 等价写法

`pytest.raises` 的内部逻辑，可以近似理解为：

```python
try:
    hour_to_index(24)
except ValueError as e:
    if not re.search("hour", str(e)):
        raise Failed("DID NOT MATCH")
    # 匹配成功：什么都不做，异常被吞掉
else:
    raise Failed("DID NOT RAISE <class 'ValueError'>")
```

注意几个点：

- `try` 只包住 `hour_to_index(24)`；
- 如果抛的是 `ValueError`，进入 `except`；
- 如果抛的是 `TypeError`，`except ValueError` 抓不到，异常继续往外抛，测试失败；
- 如果什么都没抛，走 `else`，主动报 `DID NOT RAISE`；
- 如果类型对但信息不匹配，报 `DID NOT MATCH`。

#### 实际走一遍

调用：

```python
hour_to_index(24)
```

函数内部：

```python
if not 0 <= hour <= 23:
    raise ValueError(f"hour must be between 0 and 23, got {hour}")
```

因为 `24` 不在 `0..23`，抛出：

```python
ValueError("hour must be between 0 and 23, got 24")
```

`pytest.raises` 收到后：

1. 类型是 `ValueError`，符合；
2. `str(e)` 是 `"hour must be between 0 and 23, got 24"`；
3. `re.search("hour", ...)` 能找到 `"hour"`，符合；
4. 返回 `True`，异常被吞掉；
5. `with` 后面的代码继续执行（这里没有代码了）；
6. 测试函数结束，pytest 记为通过。

#### 三种失败情况

**没抛异常：**

```python
with pytest.raises(ValueError):
    hour_to_index(1)   # 正常返回 1
```

结果：

```text
Failed: DID NOT RAISE <class 'ValueError'>
```

**抛了别的异常：**

```python
with pytest.raises(ValueError):
    1 / 0
```

`ZeroDivisionError` 不是 `ValueError`，不会被捕获，测试失败并显示原始异常。

**异常信息不匹配：**

```python
with pytest.raises(ValueError, match="分钟"):
    hour_to_index(24)
```

类型对了，但信息里没有“分钟”，`match` 失败，测试失败。

#### `match` 是正则，不是普通字符串

```python
match="hour"
```

等价于：

```python
re.search("hour", str(exception))
```

逐项解释：

- `re` 是 Python 的正则表达式模块。
- `re.search(模式, 文本)` 会扫描整个文本，找第一个匹配的位置。
- 找到返回 `Match` 对象，找不到返回 `None`。
- `Match` 对象在 `if` 里是真值，`None` 是假值。

实际演示：

```python
import re

text = "hour must be between 0 and 23, got 24"

re.search("hour", text)
# <re.Match object; span=(0, 4), match='hour'>

re.search("minute", text)
# None

bool(re.search("hour", text))    # True
bool(re.search("minute", text))  # False
```

`str(exception)` 是异常的消息文本：

```python
try:
    hour_to_index(24)
except ValueError as e:
    print(type(e))   # <class 'ValueError'>
    print(str(e))    # hour must be between 0 and 23, got 24
    print(repr(e))   # ValueError('hour must be between 0 and 23, got 24')
```

所以 `match="hour"` 的意思是：

> 异常消息里**任意位置**出现 `hour` 就算匹配，不是要求整句等于 `hour`。

它和 `re.match` 不是一回事：

| 函数 | 从哪里开始匹配 |
|---|---|
| `re.match` | 只从字符串开头匹配 |
| `re.search` | 扫描整个字符串，任意位置 |
| `re.fullmatch` | 整个字符串必须完全匹配 |

pytest 的 `match` 参数用的是 `re.search`，所以消息开头不是 `hour` 也能匹配。

正则的简单例子：

```python
match=r"got \d+"      # got 后面跟数字
match=r"(hour|minute)" # hour 或 minute
match=r"^hour"        # 必须以 hour 开头
match=r"24$"          # 必须以 24 结尾
match=r"(?i)hour"     # 忽略大小写
```

特殊字符要转义，比如想匹配字面量小数点：

```python
match=r"3\.14"
```

如果只想做普通子串判断，不用正则也可以：

```python
assert "hour" in str(e)
```

pytest 用正则，是为了让 `match` 支持更复杂的匹配。

#### 为什么 with 里只放一行

```python
with pytest.raises(ValueError):
    hour_to_index(24)
```

只放“预期会报错”的那一行。如果写成：

```python
with pytest.raises(ValueError):
    x = 1
    y = 2
    hour_to_index(24)
```

前面任何一行抛了 `ValueError`，测试都会通过，但根本不是你想测的目标。**范围越小，测试越准确。**

### 模块 1 · FastAPI

#### 1.1 HTTP 基础

**HTTP = HyperText Transfer Protocol，超文本传输协议。**

一句话：

> 浏览器和服务器之间“一问一答”的规则。

##### 请求与响应

一次 HTTP 交互由两部分组成：

```text
浏览器  ──请求（Request）──▶  服务器
浏览器  ◀──响应（Response）──  服务器
```

请求示例：

```http
GET /hello/张三?lang=en HTTP/1.1
Host: 127.0.0.1:8000
Accept: application/json
```

响应示例：

```http
HTTP/1.1 200 OK
content-type: application/json
content-length: 30

{"message":"Hello, 张三"}
```

##### URL 的组成

```text
http://127.0.0.1:8000/hello/张三?lang=en#top
└─┬─┘ └────┬────┘ └┬┘ └──┬──┘ └──┬──┘ └┬┘
协议     主机      端口   路径     查询参数 片段
```

| 部分 | 例子 | 作用 |
|---|---|---|
| 协议 | `http` / `https` | 用什么规则通信 |
| 主机 | `127.0.0.1` | 服务器地址 |
| 端口 | `8000` | 服务器上的哪个服务 |
| 路径 | `/hello/张三` | 要访问哪个资源 |
| 查询参数 | `?lang=en` | 附加条件 |
| 片段 | `#top` | 页面内定位，不发给服务器 |

##### 常用方法

| 方法 | 语义 | 本项目例子 |
|---|---|---|
| `GET` | 读取资源 | 查命盘、查历史 |
| `POST` | 创建资源 | 提交生辰、创建解读 |
| `PUT` | 整体更新 | 更新用户资料 |
| `PATCH` | 部分更新 | 改一个字段 |
| `DELETE` | 删除资源 | 删除历史记录 |

`GET` 通常不带请求体；`POST` 通常把数据放在请求体里，用 JSON。

##### 常用状态码

| 状态码 | 含义 | 什么时候出现 |
|---|---|---|
| `200 OK` | 成功 | 正常返回 |
| `201 Created` | 创建成功 | POST 新建资源 |
| `204 No Content` | 成功但无内容 | 删除成功 |
| `400 Bad Request` | 请求格式错 | 手写 JSON 不合法 |
| `401 Unauthorized` | 未认证 | 没带 Key |
| `403 Forbidden` | 无权限 | 带了 Key 但权限不够 |
| `404 Not Found` | 路径不存在 | URL 写错 |
| `405 Method Not Allowed` | 方法不对 | 用 GET 调只支持 POST 的接口 |
| `422 Unprocessable Entity` | 参数校验失败 | 日期格式不对、缺字段 |
| `429 Too Many Requests` | 请求过多 | 触发限流 |
| `500 Internal Server Error` | 服务器内部错误 | 代码抛异常 |
| `502 Bad Gateway` | 上游错误 | 反向代理连不上后端 |
| `503 Service Unavailable` | 服务不可用 | 维护或过载 |

重点区分：

- `404`：**路径**不存在。
- `422`：路径存在，但**参数**不合法。
- `500`：代码自己崩了。

##### 请求头与请求体

请求头（Headers）放元信息：

```http
Content-Type: application/json
Authorization: Bearer sk-...
Accept: application/json
```

请求体（Body）放数据：

```json
{
  "birth_date": "1991-08-15",
  "birth_time": "01:00",
  "gender": "male"
}
```

响应也一样：

```http
HTTP/1.1 200 OK
Content-Type: application/json
```

```json
{"status": "ok"}
```

##### HTTP 是无状态的

服务器默认不记得上一次请求是谁发的。每次请求都要带足够的信息（比如 Token）。

这也是为什么本项目需要数据库和会话 ID：**状态要自己存**。

##### 用 curl 发请求

`curl` 是命令行 HTTP 客户端。

```bash
# GET，显示响应头
curl -i http://127.0.0.1:8000/health

# GET，带查询参数
curl "http://127.0.0.1:8000/hello/张三?lang=en"

# POST，发 JSON
curl -X POST http://127.0.0.1:8000/charts \
  -H "Content-Type: application/json" \
  -d "{\"birth_date\":\"1991-08-15\"}"
```

参数：

- `-i`：显示响应头。
- `-sS`：安静模式，但显示错误。
- `-X POST`：指定方法。
- `-H`：加请求头。
- `-d`：请求体。

##### REST 是什么

REST 是一种 API 设计风格：

- 用 URL 表示资源：`/charts`、`/charts/{id}`；
- 用方法表示动作：`GET` 查、`POST` 建、`DELETE` 删；
- 用状态码表示结果。

本项目的接口会按这个风格设计：

```text
POST   /api/v1/charts          创建命盘
GET    /api/v1/charts/{id}     查命盘
POST   /api/v1/readings        创建解读
GET    /api/v1/readings/{id}   查解读
GET    /api/v1/history         查历史
```

#### 1.6 前置：SSE 是什么

**SSE = Server-Sent Events（服务器发送事件）**。

它让浏览器发一次请求后，**连接不关闭**，服务器持续往浏览器推送文本。

##### 和普通 HTTP 的区别

| | 普通 HTTP | SSE | WebSocket |
|---|---|---|---|
| 方向 | 一问一答 | 服务器 → 浏览器单向 | 双向 |
| 连接 | 响应完就结束 | 保持打开 | 保持打开 |
| 协议 | HTTP | HTTP | 独立协议（握手基于 HTTP） |
| 数据 | JSON/HTML/文件 | UTF-8 文本 | 文本/二进制 |
| 浏览器 API | `fetch` | `EventSource` 或 `fetch` 流 | `WebSocket` |
| 自动重连 | 无 | 有（`EventSource` 自带） | 要自己实现 |

类比：

- 普通 HTTP：点外卖，送一次就结束。
- SSE：听电台，调到一个频道后，主持人持续说话。
- WebSocket：打电话，双方都能随时说。

##### 为什么大模型流式输出常用 SSE

1. 生成是**单向**的：服务器不断吐字，浏览器只负责显示。
2. 实现简单：一个 HTTP 响应，`Content-Type: text/event-stream`。
3. 浏览器原生支持，断线可自动重连。
4. 对代理、防火墙友好，不需要额外端口。
5. 不需要 WebSocket 的双向能力。

##### 事件格式

SSE 是纯文本，一条消息由若干字段组成，**空行表示一条消息结束**：

```text
event: content_delta
data: {"text":"紫微星在午宫，"}

event: content_delta
data: {"text":"主领导力与独立性。"}

event: done
data: {"reading_id":"r_001"}
```

规则：

- `data:` 后面的内容是数据，可以有多行，浏览器会把它们用换行拼起来。
- `event:` 是事件名，前端用 `addEventListener("content_delta", ...)` 监听。
- `id:` 是事件编号，断线重连时浏览器会带 `Last-Event-ID`。
- `retry:` 告诉浏览器重连间隔（毫秒）。
- **必须有空行**，否则浏览器认为消息还没结束。

##### 浏览器怎么收

原生方式：

```js
const es = new EventSource("/api/v1/readings/1/stream");

es.addEventListener("reasoning_delta", (e) => {
  const { text } = JSON.parse(e.data);
  appendReasoning(text);
});

es.addEventListener("content_delta", (e) => {
  const { text } = JSON.parse(e.data);
  appendContent(text);
});

es.addEventListener("done", () => es.close());
es.onerror = () => {
  // EventSource 会自动重连；也可以在这里做降级
};
```

限制：`EventSource` 只能发 GET，不能带自定义请求头。如果接口需要 POST 或鉴权，就用 `fetch` 读响应流：

```js
const res = await fetch("/api/v1/readings/stream", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ chart_id: "ch_001", question: "看事业" }),
});

const reader = res.body.getReader();
const decoder = new TextDecoder();
// 按 "\n\n" 切分事件，再解析 event/data
```

协议仍然是 SSE，只是接收方式换成了 `fetch`。

##### FastAPI 怎么发

```python
from fastapi.responses import StreamingResponse
import json

async def event_stream():
    yield "event: content_delta\ndata: " + json.dumps(
        {"text": "紫微星在午宫"}, ensure_ascii=False
    ) + "\n\n"
    yield "event: done\ndata: {}\n\n"

return StreamingResponse(
    event_stream(),
    media_type="text/event-stream",
    headers={
        "Cache-Control": "no-cache",
        "X-Accel-Buffering": "no",
    },
)
```

注意：

- `ensure_ascii=False`：中文不转成 `\uXXXX`。
- `X-Accel-Buffering: no`：防止 Nginx 缓冲，导致“一次性吐出”。
- 生成器里不要做长事务；流式期间数据库连接要短。

##### 本项目的 SSE 事件

| 事件 | 作用 |
|---|---|
| `meta` | 本次解读的 ID、模型、开始时间 |
| `reasoning_delta` | 推理过程的增量文本 |
| `content_delta` | 正式回答的增量文本 |
| `citation` | 一条引用来源 |
| `heartbeat` | 心跳，防止代理断开 |
| `done` | 正常结束 |
| `error` | 错误信息，前端显示可读提示 |

##### 常见坑

1. 忘了空行：前端收不到完整事件。
2. 代理缓冲：本地可能正常，一上代理就变成最后一次性输出。
3. 中文乱码：没有统一 UTF-8，或 `json.dumps` 没加 `ensure_ascii=False`。
4. 客户端断开后服务器还在生成：要监听 `request.is_disconnected()`，及时停止，省 token。
5. 每个 token 都 `setState`：React 会卡；要按时间窗口批量刷新。
6. 没有心跳：长时间无输出时，中间代理可能掐断连接。
