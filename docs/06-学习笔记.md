## 0. 怎么用这份笔记

每个知识点按同一结构记：

```text
概念：它是什么
为什么：解决什么问题
类比：用生活里的东西怎么理解
代码：最小示例
坑：最容易错的地方
项目：对应哪个文件/接口
```

学习建议：

1. 先看“概念 + 为什么”，不要急着背命令。
2. 命令只记 3 个最常用的，其余用到再查。
3. 每学完一节，用自己的话在“我的问题清单”里写一条。
4. 面试前只看“为什么”和“坑”，这两部分最能区分“用过”和“理解”。

## 1. 项目全貌（课程 0.1）

### 1.1 一句话

用户输入生辰，后端用**确定性算法**排出紫微斗数命盘，再用**规则引擎**判断格局，然后从**本地知识库**检索依据，交给 DeepSeek **流式**生成解读，前端用 React 把命盘和文字**逐段动画呈现**。

### 1.2 分层架构

```text
浏览器（React）
   │  HTTP / JSON / SSE
   ▼
FastAPI（接口层）
   │
   ├── 排盘服务（iztro-py）        ← 确定性，不调用 LLM
   ├── 规则引擎（格局/四化/运限）   ← 确定性，不调用 LLM
   ├── RAG（Chroma + BM25）        ← 检索依据
   ├── LLM 编排（LangGraph）       ← 推理与成文
   └── SQLite（历史/会话/引用）     ← 持久化
```

**关键边界**：计算归计算，生成归生成。

- 排盘、四化、格局：必须由代码算，结果可复现、可测试。
- 语言组织、类比、追问：交给 LLM。
- 两者之间用**结构化 JSON** 连接，而不是让 LLM 读自然语言命盘。

### 1.3 一次请求的完整生命周期

以“排盘”为例：

```text
1. 用户在 React 表单填：1991-08-15 01:00 男
2. 前端 fetch POST /api/v1/charts，body 是 JSON
3. Uvicorn 收到 HTTP 请求，交给 FastAPI
4. FastAPI 用 Pydantic 校验字段（日期合法？时辰 0-12？性别？）
5. 路由函数调用 service，service 调用 domain/chart
6. domain/chart 调用 iztro-py 算出十二宫
7. 规则引擎追加格局、四化、大限、流年压力
8. 结果存入 SQLite，返回 chart_id + JSON
9. 前端拿到 JSON，渲染十二宫并播放动画
```

以“解读”为例：

```text
1. 前端打开 SSE 连接 GET /api/v1/readings/{id}/stream
2. FastAPI 先检索知识库，拿到 top-k 片段
3. 调用 deepseek-reasoner，流式收到 reasoning_content
4. 每收到一段，就通过 SSE 推给前端
5. 推理结束后调用 deepseek-chat 生成正文，继续流式推送
6. 前端边收边渲染，最后显示引用和免责声明
```

### 1.4 为什么排盘不能交给 LLM

| 问题 | 说明 |
|---|---|
| 不可复现 | 同一生辰两次调用，模型可能给出不同星曜位置 |
| 不可测试 | 没有确定答案，无法写断言 |
| 不可解释 | 用户问“为什么紫微在午宫”，模型只能编 |
| 成本高 | 每次排盘都烧 token，而排盘本可以 1ms 算完 |
| 容易错 | 安星、四化、亮度都是查表规则，模型没有表 |

所以本项目把排盘做成**工具**：LLM 可以调用它，但不能改写它的结果。

**为什么这样分**：

- `api` 只负责 HTTP，不写业务。
- `domain` 只负责领域计算，不依赖 FastAPI/数据库，方便单测。
- `services` 负责把 domain、db、llm 串起来。
- `schemas` 是接口契约，和数据库模型分开。
- `tests` 与业务代码平行，测试文件路径能对应到模块。

### 1.6 本节关键词

| 关键词 | 一句话 |
|---|---|
| 客户端/服务端 | 浏览器是客户端，FastAPI 是服务端 |
| 前端/后端 | 前端管界面，后端管数据与计算 |
| API | 前后端约定好的调用入口 |
| endpoint | 一个具体的 API 地址，如 `/api/v1/charts` |
| HTTP | 浏览器和服务端说话的语言 |
| JSON | 双方交换数据的格式 |
| SSE | 服务器持续向浏览器推送文本的技术 |
| 环境变量 | 不写进代码的配置，如 API Key |
| 确定性 | 同样输入永远得到同样输出 |

## 2. Git 与 conda 速记（课程 0.2）

> 你已有基础，这里只记项目里最容易出错的点。

### 2.1 Git 的四个位置

```text
工作区（你改的文件）
  → git add → 暂存区
  → git commit → 本地仓库
  → git push → 远程仓库（GitHub）
```

### 2.2 本项目常用命令

```bash
git status                 # 看哪些文件改了
git diff                   # 看具体改了什么
git add .                  # 加入暂存区
git commit -m "说明"        # 提交到本地
git push                   # 推到 GitHub
git log --oneline -5       # 看最近 5 次提交
```

### 2.3 `.gitignore`、`.env`、`.env.example` 的区别

| 文件 | 是否提交 | 作用 |
|---|---|---|
| `.gitignore` | 提交 | 告诉 Git 哪些文件不要管 |
| `.env` | **不提交** | 本机真实密钥与配置 |
| `.env.example` | 提交 | 配置模板，告诉别人需要哪些变量 |

本项目 `.gitignore` 已包含：

```text
.env
_refs/
data/uploads/
data/chroma/
*.db
node_modules/
__pycache__/
```

验证某个文件是否被忽略：

```bash
git check-ignore -v .env
# 输出：.gitignore:5:.env    .env
```

**最容易犯的错**：把 `.env` 提交上去。提交后再删除也仍在历史里，必须轮换 Key。

### 2.4 conda 常用命令

```bash
conda env list                  # 列出环境
conda create -n ziwei python=3.11 -y
conda activate ziwei            # 激活
conda deactivate                # 退出
conda remove -n ziwei --all     # 删除环境（慎用）
```

本项目实际创建时遇到 SSL 问题，最终命令是：

```bash
conda create -n ziwei python=3.11 -y \
  --override-channels \
  -c https://mirrors.tuna.tsinghua.edu.cn/anaconda/pkgs/main
```

**为什么用独立环境**：不同项目依赖版本冲突；独立环境删掉不影响 base；部署时容易复现。

### 3.2 conda 和 pip 的分工

| 工具 | 管什么 | 本项目怎么用 |
|---|---|---|
| conda | Python 解释器、系统级二进制依赖 | 只用来建 3.11 环境 |
| pip | PyPI 上的 Python 包 | 安装 FastAPI、LangChain 等 |

原则：**一个环境里尽量只用一种方式装包**。本项目用 conda 建环境，用 pip 装依赖。

### 3.3 为什么装这些

- `fastapi`：写 API。
- `uvicorn`：真正监听端口的服务器；FastAPI 本身只是框架。
- `pydantic`：把 JSON 变成有类型的 Python 对象，并自动校验。
- `pydantic-settings`：从 `.env` 读配置，避免把 Key 写死在代码里。
- `sqlalchemy`：用 Python 类操作数据库，减少手写 SQL。
- `alembic`：数据库结构变更的版本管理。
- `iztro-py`：排盘引擎，避免自己实现安星表。
- `pytest`：写测试。

### 3.4 `.env` 与配置读取

`.env` 已创建在项目根目录：

```text
D:\jzp_myself\命理\.env
```

你需要用记事本打开，填入：

```env
DEEPSEEK_API_KEY=sk-你的key
```

代码里不会出现 Key 字符串，而是：

```python
from pydantic_settings import BaseSettings, SettingsConfigDict

class Settings(BaseSettings):
    deepseek_api_key: str = ""
    model_config = SettingsConfigDict(env_file=".env", extra="ignore")
```

**为什么这样做**：

- Key 不进代码、不进 Git、不进日志。
- 换环境只改 `.env`，不改代码。
- 测试时可以覆盖配置，不依赖真实 Key。

### 3.5 Windows 编码问题

Python 默认输出 UTF-8，但 Windows 终端可能是 GBK，导致中文乱码。

解决：

```bash
PYTHONIOENCODING=utf-8 python your_script.py
```

或者在 Python 文件里统一：

```python
# 文件本身保存为 UTF-8；读写文件时显式指定 encoding="utf-8"
open("x.json", "w", encoding="utf-8")
```

**项目规则**：所有文件读写都写 `encoding="utf-8"`，不依赖系统默认。

### 3.6 冒烟测试：第一张盘

用一行命令验证 `iztro-py` 能工作：

```bash
PYTHONIOENCODING=utf-8 "E:/anaconda/envs/ziwei/python.exe" -c \
"from iztro_py import astro; c=astro.by_solar('1991-8-15',1,'男','zh-CN'); print(c.chinese_date); print(c.get_soul_palace().translate_name()); print(len(c.palaces)); print(c.five_elements_class)"
```

实际输出：

```text
辛未 丙申 丁巳 辛丑

```

### 3.7 输出怎么读

| 输出 | 含义 |
|---|---|
| `辛未 丙申 丁巳 辛丑` | 四柱：年柱、月柱、日柱、时柱 |
| `命宫` | 命宫所在的宫位名称（这里查询的是命宫对象） |
| `12` | 十二宫数量，完整 |
| `金四局` | 五行局，决定大限起运年龄 |

参数说明：

```python
astro.by_solar(
    "1991-8-15",  # 公历日期
    1,            # 时辰索引：1 = 丑时（01:00-03:00）
    "男",          # 性别
    "zh-CN",      # 语言
)
```

时辰索引对照：

```text
0=早子 1=丑 2=寅 3=卯 4=辰 5=巳
6=午 7=未 8=申 9=酉 10=戌 11=亥 12=晚子
```

## 4. 测试入门（课程 0.4，预告）

测试的本质是**安排 → 执行 → 断言**：

```python
def test_add():
    result = 1 + 1      # 安排 + 执行
    assert result == 2  # 断言
```

pytest 会自动发现 `test_*.py` 里的 `test_*` 函数。

本项目会用到的测试类型：

| 类型 | 测什么 | 工具 |
|---|---|---|
| 单元测试 | 排盘、规则、切分函数 | pytest |
| 接口测试 | HTTP 状态码、JSON 结构 | httpx + pytest |
| 集成测试 | 数据库 + 检索 + Mock LLM | pytest |
| E2E | 浏览器完整流程 | Playwright |
| 评测 | RAG 质量 | RAGAS |

下一节会从“为什么排盘必须测试”开始讲。

## 5. 术语表

| 术语 | 解释 |
|---|---|
| HTTP | 浏览器与服务端通信的协议 |
| REST | 用 URL 表示资源、用方法表示动作的 API 风格 |
| API | 程序之间约定好的调用接口 |
| endpoint | 一个具体的 API 地址 |
| JSON | 键值对文本格式，前后端通用 |
| 状态码 | 200 成功、400 参数错、404 不存在、500 服务端错 |
| SSE | Server-Sent Events，服务器单向持续推送 |
| ASGI | Python 异步 Web 服务器接口标准 |
| Uvicorn | 实现 ASGI 的服务器 |
| Pydantic | Python 数据校验库 |
| ORM | 对象关系映射，用类操作表 |
| SQL | 操作关系型数据库的语言 |
| 迁移 | 数据库结构的版本变更 |
| SQLite | 单文件关系型数据库 |
| 向量 | 一串数字，表示文本的语义位置 |
| Embedding | 把文本变成向量的过程 |
| Chroma | 本地向量数据库 |
| BM25 | 基于关键词频率的检索算法 |
| RRF | 倒数排名融合，把多路检索结果合并 |
| RAG | 先检索资料，再让模型基于资料回答 |
| LLM | 大语言模型 |
| token | 模型处理文本的基本单位 |
| Prompt | 给模型的指令与上下文 |
| 流式 | 模型边生成边返回，而不是等全部生成完 |
| LangChain | LLM 应用开发框架 |
| LangGraph | 用状态机编排多步 LLM 流程 |
| 引用 | 回答中标注依据来源 |
| 幻觉 | 模型编造没有依据的内容 |
