# 错误记录文档

> 项目：`ziwei-insight`
> 用途：记录搭建与开发过程中真实发生的错误、根因、修复方式与防复发措施。
> 原则：
> 1. 只记录**真实发生**的问题；尚未发生但可预见的，放在“预判问题库”，并标注 `状态：预判`。
> 2. 每条必须有**可复现的触发条件**与**验证方式**，不写“好像好了”。
> 3. 修复后 24 小时内补记，避免记忆失真。

| 字段 | 内容 |
|---|---|
| 日期 | 2026-11-04 |
| 阶段 | M0 |
| 严重级别 | P2 |
| 状态 | 已解决 |
| 环境 | Windows 10 Pro / Git Bash / Anaconda |
| 触发条件 | 执行 `python3 --version` |
| 现象 | `Python was not found; run without arguments to install from the Microsoft Store...` |

| 验证 | `python --version` 输出 `Python 3.9.13`。 |
| 防复发 | README 与所有文档统一写 `python`，不写 `python3`；CI 使用 `actions/setup-python` 的 `python`。 |
| 关联 | `docs/02-工作记录.md` D-001 |

### ERR-002 · 本机 Python 3.9.13 无法安装最新 FastAPI / LangChain

| 字段 | 内容 |
|---|---|
| 日期 | 2026-11-04 |
| 阶段 | M0 |
| 严重级别 | P0（阻塞 M1） |
| 状态 | 规避中（计划新建环境） |
| 环境 | Python 3.9.13 / Anaconda base |
| 触发条件 | 查询 PyPI 元数据：`fastapi 0.162.0`、`langchain-deepseek 1.1.1`、`langgraph 1.2.19` |

| 解决方案 | 新建 conda 环境：`conda create -n ziwei python=3.11 -y`，后续所有安装在该环境内进行。 |
| 验证 | `conda activate ziwei && python --version` 输出 3.11.x；`pip install fastapi langchain-deepseek` 成功。 |
| 防复发 | `pyproject.toml` 写 `requires-python = ">=3.11"`；CI 固定 3.11；README 首屏写明版本要求。 |
| 关联 | `docs/01-项目计划书.md` §3.2 |

**执行清单（M1 第一天）**

```bash
conda create -n ziwei python=3.11 -y
conda activate ziwei
python -m pip install -U pip
python -m pip install fastapi "uvicorn[standard]" pydantic pydantic-settings iztro-py
python -c "import iztro_py, fastapi; print('ok')"
```

> 注意：`iztro-py` 的导入名是 `iztro_py`（参考 `mingli-master/calculate_chart.py` 的 `from iztro_py import astro`）。

### ERR-006 · 创建仓库成功但 `git push` 解析不到 github.com

| 字段 | 内容 |
|---|---|
| 日期 | 2026-11-04 |
| 阶段 | M0 |
| 严重级别 | P1 |
| 状态 | 已解决 |
| 环境 | Windows 10 / Git 2.45.2 / gh 2.97.0 / VPN |
| 触发条件 | `gh repo create ziwei-insight --public --source=. --remote=origin --push` |
| 现象 | 仓库创建成功并返回 URL，但随后 `git push` 报 `fatal: unable to access '...': Could not resolve host: github.com`。 |
| 根因 | `gh` 走 API 成功，`git` 的 DNS 解析瞬时失败；未配置 `HTTP(S)_PROXY` 环境变量，Git 未跟随系统代理。VPN 连接在两次命令之间出现抖动。 |
| 解决方案 | 不做配置改动，直接重试 `git push -u origin main`，成功。 |
| 验证 | `git push` 输出 `* [new branch] main -> main`；`gh repo view` 显示 `visibility: PUBLIC`。 |
| 防复发 | 若频繁出现，给 Git 配置代理：`git config --global http.proxy http://127.0.0.1:<port>`；或使用 `gh auth setup-git`；推送失败时先 `git ls-remote` 判断网络。 |
| 关联 | ERR-004、公开仓库 https://github.com/jizhanpeng/ziwei-insight |

## 二、预判问题库（尚未发生）

> 以下问题在同类项目中高概率出现，提前给出排查路径。发生时把状态改为“已发生”，补充实际现象与根因。

### PRE-001 · `iztro-py` 与 Pydantic 版本冲突

| 字段 | 内容 |
|---|---|
| 状态 | 预判 |
| 触发条件 | 安装 `iztro-py` 时环境中已有 Pydantic v1 或其他包锁定版本 |
| 可能现象 | `ImportError`、`pydantic.errors.PydanticImportError`、字段校验异常 |
| 排查 | `pip show pydantic iztro-py`；检查是否有旧包依赖 `pydantic<2` |
| 预案 | 独立 conda 环境；必要时 `pip install "pydantic>=2.9"` 后重装 `iztro-py` |

### PRE-002 · DeepSeek API 返回 402 / 429 / 超时

| 字段 | 内容 |
|---|---|
| 状态 | 预判 |
| 触发条件 | 余额不足、并发过高、网络抖动 |
| 可能现象 | HTTP 402（余额不足）、429（限流）、`ReadTimeout`、流式中断 |
| 排查 | 打印 `status_code`、`response.text`、`request_id`；检查账户余额与控制台速率限制 |
| 预案 | `tenacity` 指数退避重试（仅幂等请求）；reasoner 超时降级 chat；全失败走模板解读；每日预算告警 |

### PRE-003 · SSE 被 Nginx/代理缓冲，前端收不到增量

| 字段 | 内容 |
|---|---|
| 状态 | 预判 |
| 触发条件 | 生产环境经 Nginx 反代 |
| 可能现象 | 所有 token 在最后一次性到达；开发者工具显示响应迟迟不刷新 |
| 排查 | 直连 Uvicorn 是否正常；检查 Nginx `proxy_buffering` |
| 预案 | 响应头 `X-Accel-Buffering: no`；Nginx `proxy_buffering off; proxy_cache off;`；15 秒心跳注释行 |

### PRE-004 · `reasoning_content` 未按预期出现在 LangChain 流中

| 字段 | 内容 |
|---|---|
| 状态 | 预判 |
| 触发条件 | 使用 `deepseek-reasoner` 流式输出 |

| 排查 | 打印原始 chunk 的 `additional_kwargs`、`response_metadata`；对照 DeepSeek 官方流式示例 |

## 三、排查顺序速查

遇到问题时按以下顺序缩小范围：

1. **版本**：`python --version`、`node -v`、`pip show <pkg>` 是否满足要求。
2. **环境**：是否激活了 `ziwei` conda 环境；`which python` 指向哪里。
3. **网络**：VPN 是否开启；PyPI / GitHub / DeepSeek 是否可达；代理环境变量是否冲突。
4. **密钥**：`.env` 是否加载；变量名是否正确；是否误提交。
5. **最小复现**：绕过 FastAPI/React，直接跑 Python 脚本或 `curl`。
6. **日志**：打开 DEBUG；记录 `request_id`；保留完整堆栈。
7. **对照**：与参考仓库同输入对比；确认是“实现错误”还是“口径差异”。
